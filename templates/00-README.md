# 專案文件範本

依[工作流程](../02-WORKFLOW.md)選用文件。新文件可用下表的預設名稱，既有專案可沿用原本的路徑及編號。請把 `＜＞` 換成實際資訊，並移除填寫提示。

| 範本 | 預設產出 | 審查問題 |
|---|---|---|
| [01 Brief](01-brief.md) | `docs/01-brief.md` | 問題有什麼證據，怎樣算成功？ |
| [02 PRD](02-prd.md) | `docs/02-prd.md` | 誰要完成什麼，怎麼驗收？ |
| [03 SRS](03-srs.md) | `docs/03-srs.md` | 規則、例外與邊界能否產生可測的預期？ |
| [04 SAD](04-sad.md) | `docs/04-sad.md` | 元件如何分工，哪些故障和取捨影響設計？ |
| [05 SDS](05-sds.md) | `docs/05-sds.md` | 資料、模組與介面契約能否獨立實作及驗證？ |
| [06 Test Plan](06-test-plan.md) | `docs/06-test-plan.md` | 重要風險怎麼驗，實際結果記在哪裡？ |

小變更可以把需求、設計及測試重點記在同一份規格或工作票。需要長期維護的資料依專案慣例保存。待決事項寫上負責人與確認時點，尚無數據的目標標為待量測。

[追溯範本](07-TRACEABILITY.md)定義需求與證據的連結方式。[經驗紀錄範本](08-LESSONS.md)整理實際偏差及後續處理。
